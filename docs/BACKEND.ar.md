# الباك إند وقاعدة البيانات — M.A.S

16 نوفمبر 2026. النطاق المعتمد: كتالوج وطلبات عروض أسعار B2B، دون شراء أو دفع إلكتروني. المرجع الوظيفي: [PRD](./PRD.ar.md).

## حالة التسليم وحدود التشغيل

تم تنفيذ API وخدمات الأعمال واختبارات محلية، ثم إعداد migrations بعد اجتياز مرحلة الباك إند الأولية. لم تُطبّق migrations على مشروع Supabase بعيد: أدوات الإضافة وإعدادات مشروعها غير متاحة في هذه الجلسة، رغم إشارة المستخدم إلى الإضافة. لا توجد مفاتيح أو بيانات إنتاج في المستودع.

الواجهات الموجودة ما زالت تستخدم `DemoProvider` وبيانات المعاينة. إضافة الـAPI لا تحول عمليات الحفظ المحلية فيها إلى عمليات حقيقية. ملف `lib/api-client.ts` يوفر عميلًا بعقد واضح للربط التالي، دون تفعيل تلقائي أو نقل بيانات تجريبية إلى قاعدة حقيقية. استبدال مصدر البيانات في كل شاشة، وربط الدخول والنماذج، واختبارات الرحلة على Supabase الفعلي، خطوات لم تنفذ بعد؛ لا يصح اعتبار الموقع إنتاجيًا أو مكتملًا بنسبة 100% في هذه الحالة.

## التصميم والعزل

`app/api/v1/[...path]/route.ts` يستقبل الطلبات، و`lib/server/controller.ts` يوجهها. العقود الصارمة في `contracts.ts`، وخدمات الأعمال في `services.ts`، والمصادقة والصلاحيات في `auth.ts` و`policy.ts`، وموصل Supabase في `supabase-repository.ts`. البيانات لا تسقط إلى ذاكرة بديلة عند تعطل الحفظ. إعداد ناقص أو فشل upstream يرجع 503.

تستخدم قاعدة البيانات schema خاصًا `mas`، خارج جداول PostgREST العامة. `entities` يحمل نوع المورد ووثيقته ونسخته وتواريخها؛ العقود الخاصة بكل نوع تُراجع في الخادم. هذا اختيار مقصود لتخزين نماذج المحتوى والمواصفات المتغيرة، وليس جداول منفصلة لكل حقل. توجد views بأسماء الموارد لمراجعتها في SQL Editor، وفهارس فريدة وفهارس JSON والبحث. العلاقات التشغيلية والهوية والمهام لها جداول مستقلة:

| الجداول                           | الغرض                                                                                            |
| --------------------------------- | ------------------------------------------------------------------------------------------------ |
| `profiles`, `invitations`         | ربط Auth بالموظفين، الأدوار والحالة والدعوات                                                     |
| `entities`, `entity_links`        | المنتجات والمراجع والمحتوى والعملاء والطلبات والعروض والوسائط؛ علاقات تمنع حذف المراجع المستخدمة |
| `variants`                        | SKU فريد بدون حساسية لحالة الحروف، منتج ووحدة، وحفظ المتغيرات المتقاعدة للتاريخ                  |
| `sales_items`                     | بنود الطلبات وعلاقات المنتج/الوحدة ولقطات ثابتة للكود والاسم                                     |
| `events`, `audit_logs`            | تاريخ المبيعات وسجل عمليات الإدارة والتصدير دون نسخ البيانات الشخصية في سجل التدقيق              |
| `policy_versions`, `consents`     | النص القانوني المنشور وإصدار الموافقة ومصدرها ووقتها                                             |
| `idempotency_keys`, `rate_limits` | تزامن الإرسال والحدود الدائمة؛ عناوين الشبكة تُستخدم كبصمة HMAC ولا تحفظ كعنوان خام               |
| `jobs`                            | ملفات PDF وفحص ورفع الملفات وحذفها، lease ومحاولات وحالة وخطأ آمن                                |

كل الجداول بها RLS، ولا تمنح `anon` أو `authenticated` وصولًا مباشرًا إلى schema أو الجداول. دوال القراءة العامة تُرجع حقولًا مسموحة صراحة، بما فيها نص البحث حتى لا تكشف نتائج البحث ملاحظات داخلية. القراءة الخاصة تطبق الدور والإسناد من `auth.uid()` وJWT موثوق. دوال الكتابة مقصورة على `service_role`؛ يستدعيها الباك إند بهوية موظف تحقق منها، ثم تعيد قاعدة البيانات فحص نشاطه ودوره وMFA، وتنفذ CAS على `version` والمعاملة. لا يستطيع SDK في المتصفح تجاوز تحقق الخادم باستدعاء دالة كتابة مباشرة.

## الـAPI

الأساس `/api/v1`. الفهرس الآلي: `GET /api/v1/openapi`. أسماء حقول JSON بـcamelCase، والمخططات الكاملة والحدود في [contracts.ts](../lib/server/contracts.ts).

| المسارات                                                                                  | الاستخدام                                                                                    |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `GET catalog/products`, `catalog/products/:id`, `catalog/facets`                          | كتالوج عام وفلاتر وتفاصيل                                                                    |
| `GET catalog/{categories,brands,sectors}[/:id]`                                           | المراجع العامة المنشورة                                                                      |
| `GET content/:key`                                                                        | المحتوى المنشور؛ المفاتيح المحجوزة `navigation`, `locations`, `settings`, `units` تعيد قوائم |
| `POST quote-requests`, `inquiries`                                                        | حفظ عام، مع ترويسة `Idempotency-Key` من 16–100 حرف آمن                                       |
| `POST auth/login`, `logout`, `recover`, `password`                                        | مصادقة واستعادة؛ callback يستبدل كود PKCE ويحول لصفحة تعيين كلمة المرور                      |
| `GET auth/me`, `auth/mfa/factors`; `POST auth/mfa/{enroll,challenge,verify,unenroll}`     | جلسة وMFA؛ إزالة عامل تتطلب aal2 وإبقاء عامل موثق للأدوار المميزة                            |
| `GET/POST admin/:resource`; `GET/PATCH/DELETE admin/:resource/:id`                        | عمليات الموارد حسب صلاحيتها؛ الطلبات والعروض لها الأفعال المحددة أدناه ولا تُحذف كسجلات عادية |
| `POST admin/{products,categories,brands,sectors,content}/:id/{publish,unpublish,archive}` | نشر وحالة مع `version` متوقع                                                                 |
| `POST admin/{quote-requests,inquiries}/:id/{assign,events,transitions}`                   | إسناد وملاحظات وانتقال حالة                                                                  |
| `PATCH admin/{quote-requests,inquiries}/:id`                                              | `{version, priority?, followUpAt?, contactId?}`                                              |
| `POST admin/inquiries/:id/convert`                                                        | `{version, items}`؛ تحويل مرة واحدة                                                          |
| `POST admin/quote-requests/:id/quotations`                                                | إنشاء مسودة؛ `PATCH admin/quotations/:id` للتعديل                                            |
| `POST admin/quotations/:id/{issue,revise,transitions}`                                    | `{version,status,reason?,channel?}`؛ status مطلوب في عقد الانتقال حتى issue/revise           |
| `GET admin/quotations/:id/download`                                                       | URL خاص صالح 60 ثانية بعد اكتمال مهمة PDF                                                    |
| `POST admin/media` ثم `POST admin/media/:id/complete`                                     | تهيئة رفع ثم طلب الفحص بعد رفع bytes إلى الرابط الموقّع؛ لا تعني complete اعتماد الملف        |
| `GET admin/media/:id/download`; `PATCH/DELETE admin/media/:id`                            | تنزيل ملف جاهز وتعديل بياناته أو حذفه مع حماية الاستخدام                                     |
| `POST admin/exports`; `POST admin/imports/{preview,apply}`                                | تصدير CSV أو استيراد ملف بمعاينة موقعة                                                       |
| `POST admin/products/bulk`                                                                | `{operation:'archive'                                                                        | 'unpublish',items:[{id,version}]}` |
| `GET admin/reports`, `admin/audit-log`, `admin/team`; `POST/PATCH admin/team[/id]`        | التقارير والتدقيق والفريق حسب الدور                                                          |
| `GET health`; `GET/POST internal/jobs`                                                    | جاهزية ومعالج مهام محمي بسر مستقل                                                            |

تعديل مورد عام مثل منتج أو جهة اتصال يستخدم `{version, data}`؛ `data` هو النموذج الكامل الذي يسمح به مخطط المورد، وليس دمجًا عشوائيًا لحقول. المسودات المنشورة/المؤرشفة تنتقل عبر أفعال النشر. تحديث كل المتغيرات ممكن ضمن المنتج؛ إضافة متغير منفرد متاحة أيضًا عبر `POST admin/products/:id/variants` بنفس الغلاف.

فلاتر GET: `page`, `pageSize` (حتى 48)، `locale`, `q`, `status`, `category`, `brand`, `sector` (قوائم مفصولة بفاصلة)، `availability`, `pack` (الكمية داخل العبوة)، `sort=featured|name|latest`, `assignedTo`, `from`, `to`, `attribute`, `value`. موظف المبيعات محصور بطلباته مهما أرسل من فلاتر.

النجاح: `{data,meta?}`. الخطأ: `{error:{code,message,fieldErrors?,requestId}}`. القوائم العامة والإدارية العادية تعيد meta للصفحة والعدد؛ قائمة الوسائط تعيد page داخل data. النسخة القديمة ترجع 409. الحقول أو قواعد الأعمال غير الصحيحة ترجع 422. صلاحية ناقصة/MFA ترجع 403؛ سجل خارج نطاق الموظف يرجع 404. الكتابة عبر cookies تحتاج Origin مطابقًا لـ`SITE_URL`، ولا يوجد CORS يسمح لمواقع أخرى.

مثال RFQ؛ UUIDs والوحدة وإصدار الخصوصية تُقرأ من المشروع الحقيقي:

```json
{
  "locale": "ar",
  "customer": {
    "name": "اسم العميل",
    "phone": "+201012345678",
    "preferredChannel": "phone"
  },
  "items": [{ "variantId": "UUID", "quantity": 4, "unitCode": "piece" }],
  "privacy": { "accepted": true, "policyVersion": "الإصدار المنشور" },
  "source": { "page": "/ar/request-quote" }
}
```

لا يرسل الزائر أسماء/أسعار منتجات معتمدة من عنده؛ الباك إند يبني اللقطة من السجل الفعلي ويعيد فحصها داخل المعاملة. احتفظ بنفس مفتاح idempotency عند إعادة محاولة نفس المحتوى بعد انقطاع الشبكة، واستخدم مفتاحًا جديدًا إذا غيّر المستخدم الطلب.

قالب CSV للإصدار المتصل:

```csv
slug,name_ar,name_en,family,category,brand,sku,unit,pack_quantity,pack_unit
```

المراجع تقبل UUID أو slug، والوحدة تقبل code. `family=oils|grease|bearings`؛ حقلا العبوة كلاهما فارغان أو كلاهما محددان. لا تُستنتج قيم فنية أو وحدة داخل العبوة تلقائيًا. قالب المعاينة القديم ذو 7 أعمدة لم يُبدّل تلقائيًا في الواجهة؛ يلزم استخدام هذا العقد عند الربط. preview/apply يستقبلان `{csv, token?}`. التصادم أثناء apply يلغي الملف كله ولا يغير منتجات قائمة.

## توصيل Supabase وتشغيله

1. تحديد مشروع Supabase الموجود وقراءة وضعه أولًا عند إتاحة أدوات الإضافة؛ لا reset ولا استبدال schema موجود بلا مراجعة. migrations الخمسة في `supabase/migrations` تطبق بالترتيب، أو عبر `supabase db push` عند ربط CLI بالمشروع المعني. ملفات `tests/database/bootstrap.sql` **ليست migrations ولا تطبق على Supabase**.
2. وضع قيم [`.env.example`](../.env.example) في إعدادات البيئة الآمنة، ثم إعادة نشر التطبيق. لا ترسل المفاتيح في المحادثة ولا تستخدم `NEXT_PUBLIC_` لمفتاح الخدمة. استخدم `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `SITE_URL` والأسرار المنفصلة بطول 32 حرفًا على الأقل. المتغيران القديمان anon/service_role مقبولان كبديل للمشروعات القديمة. `SITE_URL` لكل Preview يجب أن يطابق origin ذلك الـPreview.
3. إعداد Auth URL وredirect allowlist إلى `SITE_URL/api/v1/auth/callback`، وتفعيل مزود البريد المناسب للاستعادة والدعوات وإعداد TOTP. التسجيل العام لا يمنح أي صلاحية موظف، ولا يوجد مسار تسجيل موظفين من الموقع.
4. إنشاء مستخدم Auth لصاحب المشروع دون كلمة مرور ثابتة في الكود، ثم تشغيل `pnpm bootstrap:owner` بمتغيري `OWNER_USER_ID` و`OWNER_DISPLAY_NAME` المخصصين لذلك المستخدم. السكربت يعمل مرة واحدة فقط ولا يطبع السر. أول دخول يتبعه تسجيل TOTP والتحقق منه قبل أي إدارة.
5. إدخال إعدادات الشركة والوحدات والنص القانوني المعتمد ونشر سياسة الخصوصية بإصدار. لا توجد seed لمنتجات أو موافقات أو مستخدمين أو كلمات مرور إنتاجية. `health` يظل 503 قبل تهيئة أساسيات المشروع ومفتاح الخدمة وسر حدود الاستخدام. يعرض أيضًا `jobsConfigured` و`mediaScannerConfigured`؛ نجاح فحص الأساسيات لا يعني أن الماسح أو الجدولة الخارجية مفعّلان.
6. جدولة `GET/POST /api/v1/internal/jobs` بانتظام وإرسال `Authorization: Bearer <CRON_SECRET>`. يمكن ضبط Vercel Cron أو جدولة Supabase حسب الحساب المتصل؛ لا يوجد جدول بعيد مفعّل في هذه النسخة. كل استدعاء يعالج مهمة واحدة؛ عدد الاستدعاءات يضبط حسب حجم العمل. المحاولات المعلقة تعاد بعد backoff، وتسترد leases المنتهية بعد 5 دقائق؛ الأخطاء الدائمة في نوع الملف أو الفحص ترفض الملف.
7. إعداد ماسح الملفات عبر `MEDIA_SCANNER_URL` HTTPS و`MEDIA_SCANNER_KEY`. يستقبل POST bytes، و`X-Content-SHA256` وBearer خاصًا به، ويعيد `{clean:true,sha256:"نفس البصمة"}` بعد الفحص. أي غياب/فشل/بصمة مختلفة يمنع النشر. هذا عقد تكامل؛ لا يوجد ماسح خارجي موصل حاليًا، ولا يتم اختراع نتيجة نجاح.
8. ربط صفحات الواجهة بالعميل ومصادر البيانات الحقيقية، وإزالة اعتماد عمليات العمل على `DemoProvider`، ثم اختبار رحلة فعلية كاملة: دخول/MFA، إنشاء منتج ونشره، RFQ محفوظ، إسناد، عرض وPDF وتنزيل خاص، ورفض وصول موظف آخر. Auth والبريد وStorage الفعليون غير مختبرين عن بعد هنا.

Buckets: `quarantine` خاص، `catalog-public` عام للملفات المعتمدة فقط، `catalog-private` خاص، `sales-private` خاص للعروض. الروابط الخاصة صالحة لمدة 60 ثانية. معالج الصور يعيد ترميز WebP بحد أبعاد وحجم، وPDF يراجع بنيته ويرفض المحتوى النشط؛ فحص البرمجيات الخبيثة يظل مطلوبًا أيضًا.

`pnpm test` يشمل حسابات الفرونت وخدمات الباك إند وHTTP ونوع وحجم الملفات وPDF. اختبارات قاعدة البيانات تنشئ PostgreSQL 17 مع تعريفات اختبار محدودة لـAuth وStorage، تطبق migrations، وتختبر RLS/grants والصلاحيات وidempotency وCAS والمراجعات والمعاملات. ثم تختبر اتصالات متوازية للإرسال والنسخ وحدود الاستخدام وleases. هذا لا يحل محل اختبار Supabase Auth/Storage الحقيقيين؛ محاكاة schemas في الاختبار ليست خدمة Supabase كاملة.

لا تحتوي اختبارات الفرونت السابقة على إثبات نجاح حفظ إنتاجي، ولا يقوم build بتطبيق migrations أو إرسال بريد أو نشر قاعدة بيانات.

نتيجة التشغيل المحلي لهذه النسخة: نجح TypeScript وبناء الإنتاج، و7 اختبارات للحسابات والفرونت، و22 اختبارًا لخدمات الباك إند وHTTP والملفات، و44 تحققًا في PostgreSQL، واختبار متزامن للإرسال والنسخ وحدود الاستخدام والمهام. فحص HTTP لنسخة الإنتاج أعاد 200 للرئيسية والكتالوج العربي/الإنجليزي وصفحة الدخول، و503 للقراءة/الحفظ المعتمدين على Supabase غير المهيأ، و404 لمسار API غير معروف. فهرس OpenAPI صالح ويحتوي 96 مسارًا موثقًا؛ هذا العدد ليس عدد اختبارات رحلات مكتملة. تم التأكد من تضمين خط PDF في ملف tracing للنشر.
