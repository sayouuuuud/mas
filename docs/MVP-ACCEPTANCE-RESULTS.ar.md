# نتائج قبول تحديث الإدارة وربط المحتوى

التاريخ: 18 نوفمبر 2026.

## ما تغير

- الموقع يقرأ الشركة والفروع والتصنيفات والعلامات والقطاعات وصور ومحتوى الرئيسية من قاعدة البيانات وStorage.
- استيراد أولي قابل للتكرار لا يستبدل تعديلًا موجودًا: 83 سجلًا، منها 21 صورة وشعارًا خضعت لمسار المعالجة الفعلي. المصدر لا يحتوي منتجات SKU، لذلك لم تُختلق مواصفات أو منتجات مصنّعين.
- اختيار المراجع بالبحث وصفحات الخادم، مع تحميل المرجع المحدد حتى إذا كان خارج الصفحة الحالية وإضافة سريعة من النماذج.
- رفع الصور داخل المنتج والتصنيف والعلامة والمحتوى وإعدادات الشركة، ومعرض مرتب وملفات TDS/SDS/PDF. الصور تعاد معالجتها؛ لا تُعلن جاهزة قبل انتهاء المعالجة.
- وحدات للبيع أو القياس أو الاستخدامين، مع وحدات شائعة وقوالب خواص اختيارية، وحفظ مسودات المنتجات قبل استكمال متطلبات النشر.
- الطلبات والاستفسارات تربط بجهة اتصال ومؤسسة داخل معاملة واحدة. لا تستبدل بيانات العميل القديمة ببيانات الزائر، وتترك التكرار الملتبس للمراجعة. سجل العميل والمؤسسة يشمل الطلبات والاستفسارات والعروض مع صفحات كاملة وحماية الحذف.
- المحتوى يحتفظ بالمرفقات ويشمل صورًا وشرائح وبطاقات ونقاطًا بالعربية والإنجليزية. لغة عرض السعر مستقلة عن لغة الواجهة، والوصفان محفوظان. الإصدار يحتفظ ببيانات الشركة وشعارها ويولد PDF خاصًا.
- أرقام التقارير، فلتر مجموعة المنتجات، عرض المحمول، وتنبيهات التغييرات غير المحفوظة وتعارض النسخ أُصلحت.

## أدلة الاختبار

- `pnpm typecheck` و`pnpm build`: ناجحان.
- `pnpm test`: 10 اختبارات نماذج/استعلامات أمامية و39 اختبار خادم ناجحًا.
- تطبيق جميع migrations واختبارات `tests/database/integration.sql` على PostgreSQL 17 معزول: ناجح. تغطية إضافية للربط الذري، منع حذف تاريخ العميل، حفظ المسودة الناقصة، إعادة الاستيراد، منع استبدال بيانات العميل، الصفحة الثانية بعد 48 طلبًا، أرقام التقارير وفلتر المجموعة.
- `tests/browser/smoke.cjs`: 30 فحص صفحة/مقاس بالعربية والإنجليزية، مع رفض شاشة الخطأ حتى مع HTTP 200.
- `tests/browser/workspaces.ts`: اختبارات عقد واجهة مع API معترض، تشمل الحفظ وإعادة الفتح والتعارض والإصدار؛ ليست دليل تخزين حقيقي.
- `tests/browser/live-acceptance.cjs`: رحلة منفصلة على خدمات Auth وREST وStorage وNext الفعلية محليًا، دون اعتراض API: دخول وMFA، مسودة، SKU، رفع صورة من النموذج، نشر منتج، إرسال طلب زائر، ظهوره وربطه بالعميل والمؤسسة، حماية السجل، حفظ الوصفين، إصدار PDF وتنزيله، 24 صفحة إدارة/علاقات على المحمول، وصور الرئيسية من Storage.
- إعادة الاستيراد محليًا: صفر سجلات جديدة، 83 سجلًا موجودًا، 21 صورة جاهزة. لا تستخدم fixtures المحلية لملء الإنتاج.

## التشغيل وإعادة الاختبار

- شغّل اختبارات قاعدة البيانات المعتادة عبر `pnpm test:db` في بيئة Docker متاحة.
- اختبار القبول الفعلي يحتاج بيئة محلية مستقلة وملف اعتماد خارجي في `E2E_CREDENTIALS_FILE` و`E2E_URL`؛ يرفض قاعدة التطبيق العامة، ولا تُحفظ كلمات المرور أو أسرار TOTP في المستودع.
- الاستيراد الأولي يتطلب اعتماد خادم، و`IMPORT_EXPECTED_PROJECT` المطابق للمشروع المقصود، وتشغيل Node مع شرط `react-server`. لا يشمل نشر الخصوصية أو الشروط ولا إنشاء حسابات أو طلبات اختبار في الإنتاج.
- تحديث الإنتاج المسجل: `20261118071701_mvp_integrated_workflows.sql`.

## المتبقي قبل استقبال العملاء

نشر نصوص الخصوصية والشروط ينتظر اعتماد المستخدم للنصين الحاليين. SMTP وتسليم البريد الخارجي يحتاجان إعداد بيانات حساب البريد؛ اختبار Mailpit المحلي لا يثبت تسليم Gmail. يضيف صاحب المشروع بيانات المنتجات الفعلية والمقاسات والمواصفات المعتمدة. إعداد فحص الملفات المعتمد هو `validation_only` في Production وPreview، ويجب عدم وصفه بأنه فحص فيروسات خارجي. يجب استبدال كلمة مرور حساب التجربة قبل استخدامه لحساب إدارة فعلي.
